Vom Namen zur Seite

DNS

Das Domain Name System übersetzt Namen wie www.beispiel.de in IP-Adressen. Der Resolver (meist beim Router oder Anbieter) fragt sich durch: erst einen Root-Server nach „.de“, dann den .de-Server nach „beispiel.de“, dann dessen eigenen Nameserver nach „www“. Antworten werden für die Dauer der TTL zwischengespeichert.

TCP

Vor dem ersten Byte vereinbaren Browser und Server eine Verbindung mit dem Drei-Wege-Handschlag: SYN, SYN-ACK, ACK. Das kostet eine Umlaufzeit (RTT). Danach beginnt TCP vorsichtig mit wenigen Paketen und verdoppelt die Menge pro Umlauf (Slow Start).

TLS

TLS verschlüsselt die Verbindung und prüft per Zertifikat, dass der Server wirklich der richtige ist. TLS 1.2 braucht dafür zwei Umläufe, TLS 1.3 nur einen, bei Wiederverbindung sogar keinen (0-RTT). Das Schloss im Browser zeigt HTTPS an.

HTTP

Erst jetzt schickt der Browser die eigentliche Anfrage (GET /) und bekommt HTML zurück, danach Bilder, Skripte und Stile. HTTP/2 schickt viele Dateien über eine Verbindung, HTTP/3 läuft über QUIC (UDP) und erledigt Verbindungsaufbau und Verschlüsselung in einem Umlauf.

Häufige Fragen

Warum ist die Umlaufzeit oft wichtiger als die Bandbreite?

Bis zum ersten Byte sind mehrere Umläufe nötig (DNS, TCP, TLS, Anfrage). Bei 100 ms Umlaufzeit sind das schnell 400 ms, egal wie schnell der Anschluss ist. Erst für große Dateien zählt die Bandbreite.

Wie schnell kann ein Signal überhaupt sein?

Licht läuft in der Glasfaser mit etwa 200 000 km/s. Für 1000 km hin und zurück vergehen damit mindestens 10 ms. Router, Umwege und Warteschlangen kommen dazu.

Was bedeutet die TTL bei DNS?

Time to live: So viele Sekunden darf eine Antwort zwischengespeichert werden. Eine lange TTL spart Anfragen, verzögert aber Änderungen, etwa beim Umzug auf einen anderen Server.
